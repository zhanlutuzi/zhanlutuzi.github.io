# 我是如何搭起大模型知识结构的

我写这个系列，不是因为我已经完全懂了大模型。

恰恰相反，是因为我发现自己经常听到一些词：Transformer、MoE、FFN、RMSNorm、KV Cache、多模态、DeepSeek-V3。它们每个都像是一个独立名词，单独看好像能查到定义，但放在一起时，我并不知道它们之间是什么关系。

于是我开始问 AI。

最开始的问题很简单：

> 大模型的发展历程是什么？

这个问题本身并不难回答。它可以被整理成一条时间线：深度学习兴起，Transformer 出现，BERT 和 GPT 开启预训练时代，GPT-3 展示规模化能力，ChatGPT 让普通人真正感受到大模型，GPT-4 和 GPT-4o 把多模态能力推到更显眼的位置，DeepSeek-V3 这类模型又把大家的注意力拉回到架构效率和训练成本上。

但真正有意思的地方，不在这条时间线本身。

真正有意思的是，时间线上的每个节点都会引出一个新的问题。

## 第一个问题：GPT-4 为什么叫多模态

当我看到 GPT-4 被称为多模态模型时，我的第一反应是疑惑。

如果一个模型主要和我聊天，它为什么是多模态？

后来我才意识到，“多模态”不是指它一定要同时输出文字、图片、声音和视频，而是指它能不能处理不同类型的信息。GPT-4 在发布时被 OpenAI 描述为能够接受图像和文本输入、输出文本的大型多模态模型。到了 GPT-4o，事情又进一步变化，它把文本、视觉和音频放进更统一的模型能力里。

这个问题让我第一次意识到：理解大模型，不能只看“它会不会聊天”，还要看它能接收什么输入、输出什么内容，以及这些能力是拼接出来的，还是在模型里更深地融合了。

于是知识结构里出现了第一条分支：

```text
能力演化
  -> 文本理解
  -> 文本生成
  -> 图文输入
  -> 音频、视觉、文本统一处理
```

## 第二个问题：大模型的基础架构都一样吗

接下来我问：这些大模型的基础架构都一样吗？

答案是：不完全一样，但很多现代大模型都绕不开 Transformer。

这句话本身又不够。我需要知道 Transformer 到底在模型里干什么。

于是我开始把它拆开看。一个简化的 Transformer Block，大体可以理解成两件事：

```text
Attention：让不同 Token 之间互相看见，理解上下文关系
FFN：对每个 Token 的表示做进一步加工
```

这时候，知识结构不再只是时间线，而是开始变成立体结构。

```text
大模型
  -> Transformer
      -> Attention
      -> FFN
      -> 残差连接
      -> Norm
```

我以前看到这些词，会觉得它们是并列的名词。现在我知道，它们其实都在数据流里的不同位置上。

## 第三个问题：FFN 到底是什么

在理解 Transformer 的过程中，我遇到了 FFN。

一开始我只是把它当成一个普通的神经网络层。后来继续问下去，才发现它比我想象的重要。

Attention 更像是在做信息调度：当前这个 Token 应该看哪些上下文？哪些词对它更重要？

FFN 更像是在做特征加工：拿到 Attention 聚合后的信息以后，再进一步判断这个表示里有哪些模式、哪些语义、哪些可能指向下一个词的知识。

更关键的是，有研究把 Transformer 的 FFN 层解释成一种 Key-Value Memory。简单说，FFN 里的第一层像是在匹配某种输入模式，第二层则会影响接下来输出词的概率分布。

所以我形成了一个很重要的理解：

> 模型的知识不是像数据库一样存成一条条文本，而是被压缩进参数里。FFN 是这种“参数化知识”的重要承载位置之一。

这句话对我很重要。因为它把“训练数据”“模型参数”“模型记忆”这几个概念连起来了。

## 第四个问题：MoE 为什么会出现

理解 FFN 之后，MoE 就容易理解很多。

如果 FFN 很重要，而且占了模型大量参数，那么模型越做越大时，FFN 自然会变成计算成本的关键部分。

普通 Dense 模型的问题是：每次推理时，大部分参数都要参与计算。

MoE 的思路是：不要每次都让所有参数上场。把原来一个大的 FFN 拆成很多“专家”，再让 Router 根据当前 Token 选择其中一部分专家参与计算。

于是我对 MoE 的理解变成了一句话：

> MoE 不是推翻 Transformer，而是改造 Transformer 里的 FFN 部分，让模型拥有更大的总容量，但每次只激活其中一小部分。

这句话比“MoE 是 Mixture of Experts”这种定义有用得多。因为它告诉我 MoE 在结构里的位置，也告诉我它为什么出现。

## 第五个问题：数据到底怎么流过 DeepSeek-V3

当我理解了 Token、Embedding、Attention、FFN、MoE、RMSNorm 这些词以后，我又问了一个更具体的问题：

> 如果我输入一句话，数据到底会流经 DeepSeek-V3 的哪些层？

这一步非常关键。

因为在这之前，我是在理解一个个概念；到了这一步，我开始把概念放回同一条数据流里。

一个简化的数据流可以写成：

```text
输入文字
  -> Tokenizer，把文字切成 Token
  -> Embedding，把 Token 编号变成向量
  -> 多层 Transformer Block
      -> RMSNorm，稳定数值范围
      -> MLA / Attention，处理上下文关系
      -> 残差连接，保留原始信息
      -> RMSNorm，再次稳定数值
      -> MoE / FFN，调用专家做特征加工
      -> 残差连接
  -> Final RMSNorm
  -> LM Head，把向量映射回词表
  -> Softmax，得到下一个 Token 的概率
  -> 输出下一个 Token
```

看到这条流程之后，很多概念终于不再悬空。

RMSNorm 不是一个孤立名词，它是数据进入 Attention 或 MoE 前的“稳压器”。

Attention 不是全部智能，它主要负责让 Token 之间交换信息。

FFN 不是可有可无的附属层，它承担了大量特征加工和知识调用。

MoE 不是一个独立模型类别，它经常出现在 Transformer Block 的 FFN 位置上。

LM Head 不是在“理解”语言，而是把模型内部向量重新投影到词表空间，准备预测下一个 Token。

## 我最后得到的知识地图

整理到最后，我发现自己真正需要的不是一堆定义，而是一张地图。

这张地图大概长这样：

```text
大模型知识结构
  |
  |-- 发展脉络
  |     |-- Transformer
  |     |-- BERT / GPT
  |     |-- GPT-3 / ChatGPT
  |     |-- GPT-4 / GPT-4o
  |     |-- DeepSeek 等高效率架构
  |
  |-- 基础架构
  |     |-- Tokenizer
  |     |-- Embedding
  |     |-- Transformer Block
  |     |-- LM Head
  |
  |-- Transformer 组件
  |     |-- Attention
  |     |-- FFN
  |     |-- Residual
  |     |-- RMSNorm / LayerNorm
  |
  |-- 现代架构优化
  |     |-- MoE
  |     |-- Router
  |     |-- MLA / GQA / MHA
  |     |-- KV Cache
  |
  |-- 能力形态
  |     |-- 文本模型
  |     |-- 多模态模型
  |     |-- 推理模型
```

这张图不一定完整，但它对我有用。

因为以后我再看到一个新名词时，我可以先问：它在这张图的哪一层？

如果它是 Tokenizer，那它属于输入处理。

如果它是 MLA，那它属于注意力机制的优化。

如果它是 MoE，那它大概率是在 FFN 位置上做稀疏激活。

如果它是 GPT-4o，那它更像是能力形态和多模态架构上的变化。

如果它是 DeepSeek-V3，那它就要放到“现代 Transformer + MoE + 注意力优化 + 工程效率”这一组里看。

## 写给未来的自己

我写这个系列，是为了给未来的自己留一条回来的路。

我不指望自己看完一次就记住所有概念。事实上，很多概念过几天就会忘。真正重要的是，当我忘了以后，我知道应该从哪里重新进入。

如果我忘了大模型怎么发展，就回到第一篇，看时间线。

如果我忘了 Transformer 怎么工作，就回到第二篇，看数据流。

如果我忘了 FFN 为什么重要，就回到第三篇，看知识如何压缩进参数。

如果我忘了 MoE 是什么，就回到第四篇，看“专家”如何替换普通 FFN。

如果我忘了 DeepSeek-V3 的结构，就回到第五篇，看一遍数据经过哪些层。

如果我想比较不同模型，就回到第六篇，看差异究竟发生在架构的哪些位置。

这就是我想建立的知识结构。

它不是为了显得我懂很多，而是为了让我在遇到新概念时，不再只是背一个定义，而是知道它应该放在哪里。
