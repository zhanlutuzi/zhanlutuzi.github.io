# FFN：模型的知识到底藏在哪里

## 一句话总结

FFN 是 Transformer 每层里的重要加工模块。它不只是“几层全连接网络”，还被研究解释为一种 Key-Value Memory。模型从训练数据中学到的很多模式和知识，会以参数形式压缩在这些层里。

## 我一开始的问题

我问过：

> 当训练数据变大，模型的“记忆”实际上是存储在 FFN 层的对吗？

这个问题很重要。因为它不再只是问“FFN 是什么”，而是在问：

> 大模型到底把知识放在哪里？

## 先说结论：基本方向对，但要更精确

可以说，FFN 是 Transformer 中承载知识的重要位置之一。

但不能简单说“所有知识都存在 FFN 里”。大模型的能力来自整个网络，包括 Attention、Embedding、残差路径、输出层等。但从很多解释性研究来看，FFN 确实承担了大量模式匹配和知识表达的作用。

我给自己的版本是：

> Attention 更像信息调度系统，FFN 更像模式加工和知识调用系统。

## FFN 在 Transformer 里在哪里

一个简化的 Transformer Block 是：

```text
输入
  -> Attention
  -> FFN
  -> 输出
```

更完整一点：

```text
输入
  -> Norm
  -> Attention
  -> 残差连接
  -> Norm
  -> FFN
  -> 残差连接
  -> 输出
```

Attention 先让当前 Token 从上下文里拿到信息。FFN 再对当前 Token 的向量进行进一步加工。

## FFN 的内部动作

一个典型 FFN 可以简化成：

```text
输入向量
  -> 第一层线性变换，通常升维
  -> 激活函数，引入非线性
  -> 第二层线性变换，降回原维度
  -> 输出向量
```

用更直观的话说：

```text
先把问题展开
  -> 在更大的空间里处理
  -> 再压缩回原来的表达空间
```

这里的“展开”很重要。它让模型有空间表达更复杂的模式，而不是只做简单线性变换。

## 为什么说 FFN 像记忆

论文《Transformer Feed-Forward Layers Are Key-Value Memories》提出了一种解释：Transformer 的 FFN 层可以看成 Key-Value Memory。

简化理解如下：

```text
输入向量
  -> 和一组 Key 匹配
  -> 激活相关的记忆槽
  -> 这些记忆槽对应的 Value 影响输出分布
```

这有点像：

```text
看到某种上下文模式
  -> 触发某些内部记忆
  -> 增加某些后续 Token 出现的概率
```

比如模型见过大量类似模式：

```text
法国的首都是 ___
```

训练之后，它不会把“法国的首都是巴黎”作为一条数据库记录保存起来，而是把这种统计关系压缩进参数中。当输入触发相关模式时，模型就更倾向于输出“巴黎”。

## 但这不是数据库

这里最容易误解。

大模型的“记忆”不是数据库式的。

数据库是：

```text
key: 法国首都
value: 巴黎
```

大模型参数里的知识更像：

```text
大量文本模式
  -> 被压缩进高维参数空间
  -> 在生成时被上下文激活
  -> 影响下一个 Token 的概率
```

所以模型会知道很多事实，也会混淆事实，甚至会生成看似合理但错误的内容。因为它不是查表，而是在根据参数和上下文计算概率。

## 为什么训练数据越多，模型知识越多

训练时，模型不断做一件事：

```text
根据前文预测下一个 Token
```

预测错了，就调整参数。大量文本反复训练之后，模型参数会逐渐吸收语言规律、事实关系、写作风格、推理模式。

FFN 因为参数量大、非线性强、每层都参与加工，所以成为这些模式的重要承载位置。

这也解释了为什么模型规模、数据质量和训练方式都很关键。

## Attention 和 FFN 的分工

我现在更愿意这样理解：

```text
Attention
  -> 当前 Token 应该参考哪些上下文？
  -> 信息从哪里来？
  -> 哪些词之间有关联？

FFN
  -> 拿到这些信息后，应该如何加工？
  -> 当前模式像什么？
  -> 哪些知识或输出倾向应该被激活？
```

这不是严格边界，但对建立直觉很有用。

## 和 MoE 的关系

理解 FFN 之后，MoE 就很好理解了。

如果 FFN 承载了大量参数和知识加工能力，那么当模型继续变大时，FFN 会变得很贵。

MoE 的思路是：

```text
不要只有一个大 FFN
  -> 拆成很多专家 FFN
  -> 每个 Token 只选择其中一部分专家
```

所以 MoE 不是凭空出现的新概念，它和 FFN 有直接关系。

## 容易误解的地方

第一，“知识在 FFN 里”不是说 Attention 没有知识，也不是说模型只有 FFN 重要。

第二，模型记忆不是数据库记忆。它是参数化、分布式、概率性的。

第三，训练数据变多不一定自动变聪明。数据质量、训练方法、模型结构和对齐方式都会影响结果。

第四，模型能说出事实，不代表它真的以人类方式理解事实。

## 这一篇我真正理解了什么

如果以后我忘了 FFN 的作用，我只需要记住：

```text
Attention 负责信息流动
FFN 负责深度加工
大量知识和模式以参数形式压缩在 FFN 等组件里
MoE 本质上是把 FFN 拆成很多专家并按需调用
```
